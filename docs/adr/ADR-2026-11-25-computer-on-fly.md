# ADR-2026-11-25: Host the computer player on Fly.io

- **Status:** Accepted
- **Approved by:** the maintainer, 2026-11-25
- **Companion:** [ADR-2026-11-25-computer-on-fly-for-dummies.md](ADR-2026-11-25-computer-on-fly-for-dummies.md)
- **Amends:** [ADR-2026-11-18-computer-player](ADR-2026-11-18-computer-player.md), the hosting choice and sections 9 and 11

## Context

ADR-2026-11-18 chose Railway Hobby ($5/month) for `apps/bot`, with Fly.io (about $2.55/month always-on) as "a fallback if Railway fails".

On 2026-11-25, when it came to deploying, the maintainer's Railway trial had already expired, with no projects. Railway needs a paid upgrade before anything can run. The maintainer opened Fly.io instead. Its plan screen offers:

- **Free:** $5 of usage every month once a card is added, up to 3 machines, and a move to Pay As You Go above $5. Without a card, only a one-time $1 starter credit.
- **Pay As You Go:** the same rates, uncapped.

**What the service needs from a host:**

- **It must not sleep mid-game.** While playing, the service only makes outbound calls to Sepolia. Railway sleeps on outbound silence; Fly's auto-stop stops a machine when it has no _inbound_ requests. So a Fly machine left to auto-stop would be stopped during games, the reason Render was rejected. On Fly it must stay on.
- **Exactly one copy may run.** Every computer wallet comes from one secret phrase. Two copies would take the same wallet to two tables, collide on transaction nonces, and spend the bank twice. Fly's first `fly deploy` creates **two** machines by default for availability, which must be prevented.
- **Its build:** `@bluff/contracts`' ABIs are generated by `hardhat compile` (`exports/abis.ts` is git-ignored). The bundle (`apps/bot/build.mjs`) leaves `@zama-fhe/sdk` and `viem` external, so the runtime needs those two installed.
- **It listens on `PORT`,** defaulting to 8080, serves `/health`, and stops cleanly on `SIGTERM`.

## Options considered

### Option A: Fly.io, one always-on machine (chosen)

- **Cost:** a `shared-cpu-1x` machine. Fly's published price, about $1.94/month with 256 MB or about $3.19/month with 512 MB, falls inside the $5 monthly allowance on the Free plan with a card, so it costs nothing in practice. It's to be confirmed on Fly's pricing page at deploy.
- **What it needs:**
  - a `Dockerfile` and a `fly.toml` in the repository;
  - `flyctl` on the maintainer's machine, with the maintainer logging in;
  - deploys from the command line.

### Option B: upgrade Railway to Hobby

$5/month, the original plan, with no new files. It needs a paid upgrade, and the maintainer moved to Fly instead.

### Option C: Render free

Rejected in ADR-2026-11-18: it sleeps mid-game and takes a minute to wake.

## Decision

**Option A.**

1. **`apps/bot/Dockerfile`,** built from the repository root:
   - a build stage on `node:24-slim` that enables pnpm through corepack (`packageManager`);
   - it installs the workspace with `--frozen-lockfile`;
   - it runs `pnpm --filter @bluff/contracts compile` to generate the ABIs;
   - it runs `pnpm --filter @bluff/bot build`;
   - a slim runtime stage with `dist/` and only the bot's production dependencies (`pnpm deploy --prod`), running `node dist/main.js` as a non-root user.
2. **`apps/bot/fly.toml`:**
   - `internal_port = 8080`, with HTTPS forced;
   - `auto_stop_machines = "off"` and `min_machines_running = 1`, so it never sleeps;
   - a `GET /health` check;
   - a 512 MB `shared-cpu-1x` machine;
   - the app name and region chosen by the maintainer at first deploy;
   - no secrets in the file.
3. **Exactly one machine:** the first deploy runs `fly deploy --ha=false`, and the machine count is checked to be 1 after each deploy. CONTRIBUTING says never to scale it above one.
4. **Secrets are set by the maintainer** in Fly's dashboard: `BOT_MNEMONIC` and `SEPOLIA_RPC_URL`. They're never typed into chat or a shell command here. `ALLOWED_ORIGINS` isn't secret: `http://localhost:3002` for testing, plus the Vercel staging and production addresses once known.
5. **Source:** deploys are run by hand from a clean checkout of the branch being served. That's `dev` for testing, and `main` once the maintainer promotes. Automatic deploys from GitHub can come later as a separate decision.
6. **Docs updated in the same change:**
   - the architecture doc's hosting section;
   - section 9's "staying awake" text (Fly: always on, so nothing about waking);
   - CONTRIBUTING's deploy steps.

   The web app's waking retry ("Waking the computer…") stays, since it also covers a restart or deploy.

7. **No code change** to the service or the web app is needed for the move.

## Diagram

```
 repo (dev, later main) ──fly deploy --ha=false──► Fly.io app (1 machine, always on)
                                                     ├─ node dist/main.js  :8080
                                                     ├─ GET /health  (Fly check)
                                                     └─ secrets: BOT_MNEMONIC, SEPOLIA_RPC_URL (dashboard)
 web app (localhost:3002 / Vercel) ──POST /seat──► https://<app>.fly.dev   (ALLOWED_ORIGINS)
 service ──RPC──► Sepolia   (games, funding, decrypting its own dice)
```

## Consequences

- **Better:**
  - the service runs with no subscription, inside Fly's free monthly allowance;
  - it never sleeps, so no player waits for it to wake;
  - the build is a Dockerfile anyone can run.
- **Costs:**
  - two small config files in the repository;
  - `flyctl` on the maintainer's machine;
  - a card on the Fly account;
  - manual deploys.
- **Risk:** a second machine would double-run the computers. It's prevented by `--ha=false` and the count check, and written into CONTRIBUTING.
- **Unchanged:** the service's code, its HTTP API, its settings names (`apps/bot/.env.example`), the web app's `NEXT_PUBLIC_BOT_URL`, and the contracts.
- **Packages:** none added or removed.

## Verification

- **A local `docker build`** from the repository root succeeds, and the image refuses to start without settings, like the existing bot smoke test.
- **`pnpm preflight`** passes.
- **After the maintainer sets the secrets and the first deploy:**
  - `fly status` shows exactly one machine, passing its `/health` check;
  - `/health` lists the bank and the computers;
  - a preflight request from `http://localhost:3002` is allowed, and one from another site is refused;
  - the maintainer plays the computer from `localhost:3002` with `NEXT_PUBLIC_BOT_URL` pointing at the Fly address.
